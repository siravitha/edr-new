# การตรวจรับและออกเลขครุภัณฑ์

ข้อตกลงผู้ใช้: เลขใหม่ `ประเภท 4 หลัก-ชนิด 3 หลัก-ลำดับ 5 หลัก/ปีงบประมาณ 2 หลัก` ลำดับแยกประเภท–ชนิด นับต่อข้ามปี เลขเดิม 4 หลักคงเดิม การตรวจซ้ำพิจารณาค่าลำดับเชิงตัวเลข ไม่ยอมให้ `0001` และ `00001` เป็นคนละลำดับ แม้ปีท้ายต่างกัน

เมนูฝ่ายพัสดุกลาง → ตรวจรับและออกเลขครุภัณฑ์ สร้างร่างรายการรับโดยไม่มีเลขทางการ บันทึกผลตรวจรับรายเครื่องตามหลักฐานลงนาม จากนั้นเจ้าหน้าที่พัสดุยืนยันออกเลขเฉพาะเครื่องที่ผ่าน ตรวจรับบางส่วนไม่เปิดสิทธิ์ออกเลขให้เครื่องอื่น ไม่ต้องรอจ่ายเงินจริง การกดซ้ำ การข้ามโรงพยาบาล บทบาทอื่น revision เก่า และการออกเลขขณะออฟไลน์ถูกปฏิเสธ

บันทึก intake ค่าลำดับ ทะเบียนทรัพย์สิน และ Log ในธุรกรรม IndexedDB เดียวกัน ใช้ Web Lock ของต้นแบบ ไม่ใช่ฐานข้อมูลส่วนกลางหลายเครื่อง ลำดับครบ 99999 จะหยุดไม่วนกลับ ไม่เปิดแก้เลขเดิมหรือเพิ่มรหัสประเภท–ชนิดใหม่ เนื่องจากยังรอข้อมูลผู้มีอำนาจอนุมัติ

บัญชีรหัสที่เปิดให้ทดลองมีเฉพาะ `7110-010` ตามตัวอย่างผู้ใช้ ไม่เดาแปลงคอลัมน์รหัสในเอกสาร 68 หน้าเป็นรหัสใหม่ รายการรหัสฉบับเต็มต้องทวนสอบก่อนเปิดใช้ การยืนยันผลตรวจรับในต้นแบบเป็นการบันทึกอ้างอิง ไม่ใช่การตรวจลายเซ็นหรืออนุมัติราชการจริง และยังไม่เชื่อมปริมาณตามสัญญาจริง

การสแกนรองรับเลขเดิม 4 หลัก เลขใหม่ 5 หลัก และป้ายข้อมูลสาธิตเดิม การค้นเลขต่างจำนวนศูนย์นำหน้าต้องมี prefix ลำดับ และปีท้ายตรงกัน การนำเข้า CSV ของทะเบียนเดิมตรวจลำดับซ้ำทั้ง 4/5 หลักข้ามปี ต้องระบุหลักฐานทะเบียนเดิมและยืนยันว่าไม่ใช่ออกเลขใหม่แทนขั้นตรวจรับ การรองรับไฟล์ Excel .xlsx ยังไม่เปิดในรุ่นนี้

รายการออกเลขใหม่เข้าทะเบียนสถานะรอรับรองพร้อมใช้ และมี accountingPending ไม่รวมในมูลค่าบัญชีสุทธิที่แสดงว่าได้รับรองแล้ว ราคาทุนบันทึกได้ แต่ยังไม่คำนวณค่าเสื่อมจริง ไม่แก้ข้อมูลเดิมย้อนหลัง

ตารางอายุและอัตราค่าเสื่อมฝ่ายบัญชีถอดจากเอกสาร 2 หน้า หัวตารางระบุ สป.สธ. เก็บปีและอัตราตามเอกสารแยกกัน คง 33% และ 6.5% ตามต้นฉบับ ไม่แปลงเป็น 100/อายุ ยังต้องตรวจวันมีผล วันเริ่มคิด มูลค่าคงเหลือ การเฉลี่ย การปัดเศษ และงวดสุดท้าย

แหล่งกรมสุขภาพจิตไม่ใช้เป็นกติกาเลขหรือค่าเสื่อมของโรงพยาบาลอุดรธานี ทะเบียนอ้างอิงเพิ่มข้อมูลเอกสารแนบผู้ใช้โดยระบุสถานะและสิ่งที่ยังต้องตรวจ
