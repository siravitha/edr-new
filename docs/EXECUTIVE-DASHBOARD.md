โรงพยาบาลอุดรธานี — พัฒนาโดย Pacific Plus IT  
วันที่จัดทำ: 1 พฤศจิกายน 2569  
สถานะ: ต้นแบบข้อมูลในเบราว์เซอร์ ไม่ใช่ระบบราชการหรือยอดบัญชีรับรอง

## 1. เป้าหมายและข้อกำหนดที่ผู้ใช้ยืนยัน

Dashboard ต้องยึดฝ่ายแผนงานและยุทธศาสตร์ ฝ่ายพัสดุกลาง ฝ่ายการเงิน ฝ่ายบัญชี และฝ่ายนิติกรเป็นแกนหลัก ไม่ใช้ทะเบียนครุภัณฑ์เป็นภาพรวมหลักแทนงานทั้งโรงพยาบาล

แต่ละฝ่ายต้องตอบได้ว่า งานเดินตามแผนหรือไม่ ติดขัดเพราะอะไร กระทบอะไร ใครต้องดำเนินการต่อ และผู้บริหารควรพิจารณาเรื่องใด การ์ดและกราฟเป็นทางเข้ารายการต้นทางและหลักฐาน ไม่ใช่ปุ่มอนุมัติหรือคำวินิจฉัยอัตโนมัติ

ดีไซน์ใช้พื้นหลังสว่าง สีประจำฝ่าย ตัวเลขเด่น กราฟแท่งซ้อน กราฟแท่งเปรียบเทียบ และกราฟเส้น สลับดูตารางได้ สีมีข้อความและจำนวนประกอบ ไม่อาศัยสีเพียงอย่างเดียว รองรับหน้าจอแคบโดยเรียงการ์ดและเลื่อนตารางแนวนอน

## 2. มุมมองและตัวกรอง

| ตัวเลือก | ความหมาย |
|---|---|
| ภาพรวมโรงพยาบาลในสิทธิ์ | รวมรายการเฉพาะหน่วยงานที่มุมมองผู้ใช้เปิดดูได้ |
| รายแผนก/ฝ่ายเจ้าของคำขอ | กรองหน่วยงานผู้รับประโยชน์ เช่น ICU แล้วติดตามงานผ่านทั้ง 5 ฝ่าย |
| ฝ่ายดำเนินงาน | แผนฯ พัสดุ การเงิน บัญชี หรือนิติกร เป็นคนละแกนกับหน่วยงานเจ้าของคำขอ |
| ปีงบประมาณของแผน | ปีของแผนต้นทาง ไม่ใช่ปีที่เกิดทุกงวดจ่ายของสัญญาหลายปี |
| แหล่งเงิน | แยกเงินงบประมาณ เงินบำรุง เงินบริจาค ตามข้อมูลต้นทาง ไม่รวมแหล่งเงินเป็นกองเดียว |
| ช่วงวันที่เริ่มรับงาน | สถานะล่าสุดของงานที่เริ่มในช่วงนั้นของแต่ละฝ่าย ไม่ใช่รายการจ่ายหรือสมุดรายวันในงวด |
| ล้างตัวกรอง | กลับภาพรวม ในหน้ารายงานเฉพาะฝ่ายยังคงฝ่ายตั้งต้นของรายงาน |

ตัวเลข กราฟ ตารางหลัก รายการเสนอพิจารณา และรายงานส่งออกใช้ตัวกรองชุดเดียวกัน การค้นหาเฉพาะตารางใช้หาข้อมูลในรายการ โดยไม่เปลี่ยนกราฟหรือขอบเขตรายงานส่งออก ระบุไว้บนช่องค้นหาอย่างชัดเจน

วันที่ผิดลำดับจะหยุดแสดงผลและส่งออกจนแก้ไข รายการที่ไม่มีวันที่เริ่มงานไม่สร้างวันที่ย้อนหลังและไม่รวมเมื่อกรองช่วงวันที่ แต่แสดงจำนวนรายการที่ขาดวันที่

## 3. สิ่งที่ผู้บริหารควรรู้และรายงานแต่ละฝ่าย

### ฝ่ายแผนงานและยุทธศาสตร์

- ความต้องการและความจำเป็นของแต่ละหน่วยงาน การเชื่อมเป้าหมาย และความพร้อมแหล่งเงิน
- คำขออยู่ที่หัวหน้าแผนก ฝ่ายแผนฯ CFO ผู้อำนวยการ หรือรอผล สสจ.อุดรธานี
- แผนที่อนุมัติ ส่งพัสดุแล้ว และแผนที่ยังต้องปรับแก้
- รายงานที่ควรมี: ความต้องการรายหน่วยงาน แผนเทียบยุทธศาสตร์ สถานะอนุมัติ วงเงินแยกแหล่งเงิน เปลี่ยนแปลงแผน และผลเทียบแผน
- รุ่นนี้คำนวณจากรายการคำขอและสถานะแผนจริงในต้นแบบ ยังไม่มีเกณฑ์คะแนนยุทธศาสตร์หรือรายงานผลลัพธ์บริการครบถ้วน

### ฝ่ายพัสดุกลาง

- แผนที่ได้รับเปลี่ยนเป็น PR และดำเนินวิธีจัดหาแล้วหรือยัง
- งานค้างที่ PR, TOR/ราคากลาง, วิธีจัดหา, สัญญา ส่งมอบ ตรวจรับ และออกเลข
- สัญญาเกินกำหนดส่งมอบ รายการตรวจรับบางส่วน และจำนวนที่ยังขาด
- รายงานที่ควรมี: ความก้าวหน้าจัดหา อายุงาน ติดตามสัญญา ตรวจรับ ผู้ครอบครอง ซ่อม ตรวจประจำปี และจำหน่าย
- รุ่นนี้คำนวณจาก PR สัญญาและงวดตรวจรับในสายงานใหม่ การรับครบของครุภัณฑ์ยังรอออกเลขจะไม่ถือว่าเสร็จในขั้นพัสดุ
- ซ่อม ประกัน ตรวจประจำปี จำหน่าย และเผยแพร่ e-GP ยังไม่ครบกระบวนการ

### ฝ่ายการเงิน

- ภาระตามสัญญา งานรอตรวจ ส่งคืน รออนุมัติ และรอบันทึกหลักฐานจ่าย
- ตรวจรับแล้วแต่ยังไม่ตั้งเบิกหรือยังไม่จ่าย ต้องดูต้นทางประกอบ ไม่อนุมานเป็นเจ้าหนี้รับรองแล้ว
- รายงานที่ควรมี: ภาระผูกพัน/แผนจ่าย สถานะเบิกจ่าย ตรวจรับยังไม่จ่าย รับ–จ่าย กระแสเงินสด เงินยืม หลักประกัน ภาษี และกระทบยอดธนาคาร
- รุ่นนี้นับเฉพาะคำขอเบิกจ่ายที่เชื่อมสายงานใหม่ ไม่รวมคำขอตัวอย่างเดิม data.payments
- ยอด PAID คือบันทึกหลักฐานจ่ายในต้นแบบ ไม่ใช่ข้อมูลยืนยันจากธนาคารหรือการสั่งโอนเงิน
- เงินสดพร้อมใช้ เงินยืม ภาษี หลักประกัน และกระทบยอดธนาคารยังไม่มีข้อมูลรับรอง

### ฝ่ายบัญชี

- เอกสารรับเข้าครบหรือไม่ มีรายการค้างตรวจอะไร และพร้อมลงบัญชีหรือปิดงวดหรือไม่
- รายงานที่ควรมี: ความครบถ้วนบัญชี งบการเงิน เจ้าหนี้ สินทรัพย์/ค่าเสื่อม สินทรัพย์ระหว่างก่อสร้าง กระทบยอด และรายการปรับปรุงสำคัญ
- รุ่นนี้นับงวดตรวจรับที่ส่งให้บัญชีตรวจเอกสาร โดยทำหลังตรวจรับได้ ไม่ต้องรอจ่ายเงิน
- “เสร็จในขั้นของฝ่าย” ในการ์ดบัญชีหมายถึงตรวจเอกสารแล้วเท่านั้น ยังไม่ลงสมุดรายวัน ไม่รับรองค่าเสื่อม และไม่เปลี่ยนยอดสินทรัพย์สุทธิ
- ผังบัญชี สมุดรายวัน บัญชีแยกประเภท ปิดงวด และ New GFMIS Thai ยังไม่เปิดใช้งานจริง

### ฝ่ายนิติกร

- ข้อหารือค้าง สัญญารอตรวจ ข้อเท็จจริงที่ขาด และเรื่องที่ต้องเสนอผู้มีอำนาจ
- รายงานที่ควรมี: ข้อหารือ/ความเห็น ตรวจร่างสัญญา กำหนดสำคัญ ข้อร้องเรียน/อุทธรณ์ ผิดสัญญา คดี และสิทธิเรียกร้อง
- รุ่นนี้นับเรื่องที่ส่งจากสายงานใหม่และคำตอบความเห็นพร้อม PDF
- “เสร็จในขั้นของฝ่าย” หมายถึงตอบความเห็นแล้ว ไม่ใช่ปิดคดีหรือยุติความเสี่ยง
- ไม่สร้างวันครบกำหนดอุทธรณ์ อายุความ หรือระดับความเสี่ยงจากอายุงาน ต้องมีข้อมูลและการยืนยันจากนิติกรก่อน

## 4. ส่วนแสดงผลที่พัฒนาแล้วในรอบนี้

1. การ์ดหลัก 5 ฝ่าย: งานเข้า กำลังดำเนินการ รอดำเนินการต่อ เสร็จในขั้นของฝ่าย และแยกยกเลิก
2. กราฟแท่งซ้อนเปรียบเทียบสถานะงานตามฝ่าย
3. แนวโน้มงานเข้ารายเดือน สลับกราฟแท่ง/เส้น แสดง 12 เดือนล่าสุดที่มีรายการ
4. กราฟวงเงินแผนอนุมัติ ผูกพัน ตรวจรับ และหลักฐานจ่าย แยกแหล่งเงิน พร้อมตารางตัวเลข
5. งานติดขัดและประเด็นเสนอพิจารณา 8 เรื่องแรก กำหนดส่งมอบตามสัญญาที่เกินกำหนดขึ้นก่อน จากนั้นเรียงอายุงาน
6. หน้าต่างรายละเอียด: สถานการณ์ ผลกระทบที่ต้องตรวจ แนวทางเสนอ ผู้รับช่วง บริบท วันที่ มูลค่า และหลักฐาน PDF
7. เปิดพื้นที่งานต้นทาง โดยสายงานใหม่เปิดกรณี PR ที่ตรงกันได้
8. ตารางรายการต้นทาง หน้าละ 10 รายการ พร้อมค้นหาเฉพาะตาราง
9. ส่งออก CSV และ MD ตามตัวกรอง พร้อมข้อมูลที่มา สรุป 5 ฝ่าย วงเงิน แนวโน้ม รายการ และงานติดขัดใน MD
10. เมนูรายงานเดิมทั้ง 5 ฝ่ายเชื่อมหน้า Dashboard โดยเลือกฝ่ายตั้งต้นไว้ให้
11. ระบุเวลาประมวลผล กิจกรรมล่าสุด แหล่งข้อมูล และข้อจำกัดก่อนใช้ตัดสินใจ

## 5. นิยามการคำนวณและการป้องกันความเข้าใจผิด

| รายการ | ที่มาและกติกา |
|---|---|
| งานฝ่ายแผนฯ | หนึ่งรายการต่อคำขอ ใช้สถานะแผนที่คำขอนั้นสังกัดเมื่อมีแผน |
| งานฝ่ายพัสดุ | หนึ่งรายการต่อ PR สัญญาณเสร็จต้องตรวจรับครบ และครุภัณฑ์ออกเลขครบ |
| งานฝ่ายการเงิน | หนึ่งรายการต่อคำขอเบิกจ่ายใหม่ PAID นับเสร็จในขั้นบันทึกหลักฐาน |
| งานฝ่ายบัญชี | หนึ่งรายการต่องวดตรวจรับ ตรวจเอกสารแล้วนับเสร็จในขั้นเอกสาร |
| งานฝ่ายนิติกร | หนึ่งรายการต่อข้อหารือ ANSWERED นับตอบความเห็นแล้ว |
| วงเงินแผนอนุมัติ | จำนวน × ราคาต่อหน่วยของ snapshot เมื่อแผน APPROVED หรือ SENT ไม่นับร่าง/รออนุมัติเป็นยอดอนุมัติ |
| ผูกพัน | ยอดสัญญาใน PR ที่ยังไม่ยกเลิก ไม่ผูกพันจาก PR ร่าง |
| ตรวจรับ | รวมยอดงวดตรวจรับที่บันทึกผ่านในกรณี PR นั้น |
| จ่าย | รวมคำขอใหม่ที่มีสถานะ PAID เท่านั้น ไม่รวมตัวอย่างเก่า |
| อายุงาน | จำนวนวันตามวันไทยนับตั้งแต่เริ่มงาน ไม่ใช่อายุค้างในสถานะล่าสุด |
| เกินกำหนด | ใช้วันส่งมอบตามสัญญาเฉพาะกรณียังตรวจรับไม่ครบ ไม่มี SLA สมมติเป็นกฎหมาย |
| งานยกเลิก | แยกออกจากงานเสร็จและข้อเสนอค้าง ไม่รวมเป็นความสำเร็จ |
| ยอดไม่มีแหล่งข้อมูล | แสดงรอข้อมูล/ไม่อยู่ในฝ่ายที่เลือก ไม่แปลงเป็นยอดรับรองศูนย์ |

เงินในตรรกะเป็นสตางค์จำนวนเต็ม หน้าจอและรายงานแสดงบาท ไม่รวมยอดข้ามแหล่งเงิน สัญญาหลายปีแสดงยอดสัญญารวม ไม่ตีความว่าทั้งหมดเป็นรายจ่ายของปีแผนที่เลือก กราฟเงินเป็นภาพสถานะงานแต่ละฝ่าย ไม่ใช่การกระทบยอดบัญชีหรือกระแสเงินสดในงวด

## 6. สิทธิ์และความปลอดภัยในต้นแบบ

- กรองหน่วยงานในสิทธิ์ก่อนรวมตัวเลขและสร้างตัวเลือก ไม่แสดงรายการต่างโรงพยาบาล
- มุมมองพยาบาลจำกัด ICU มุมมองอื่นใช้ขอบเขตหน่วยงานตามต้นแบบเดิม ไม่ใช่ RBAC/JWT จริง
- เปลี่ยนบทบาทแล้วล้างตัวกรองและหน้ารายละเอียด Dashboard ด้วยการเริ่ม component ใหม่
- เล่มแผนที่รวมหลายหน่วยงานไม่แสดงให้ดาวน์โหลดหากมีหน่วยงานนอกขอบเขตผู้ดู
- ส่งออก CSV ป้องกันข้อความถูกตีความเป็นสูตรด้วยตัวสร้าง CSV เดิม
- บันทึก Log เมื่อเปลี่ยนตัวกรอง เปิดรายการ ดาวน์โหลดหลักฐาน และส่งออกรายงาน หากบันทึก Log ส่งออกไม่สำเร็จจะไม่ส่งออก
- ไม่มีปุ่มอนุมัติ จ่ายเงิน หรือเปลี่ยนสถานะงานจาก Dashboard
- Provider ID มีหน้าที่ยืนยันตัวตน ส่วนอำนาจปฏิบัติงานต้องกำหนดภายในระบบจริง

## 7. บริบทโครงการและข้อกำหนดที่ยังคงเดิม

- โรงพยาบาลอุดรธานีสังกัด สป.สธ. ไม่ใช้ระเบียบเฉพาะกรมสุขภาพจิตแทน นโยบายเฉพาะโรงพยาบาลต้องมีเอกสารรับรอง
- ครอบคลุมจัดซื้อ จัดจ้าง บริการ ซ่อม เช่า ก่อสร้าง และทรัพย์สินรับบริจาคตามระยะพัฒนา
- แหล่งเงินแยกเงินงบประมาณ เงินบำรุง เงินบริจาค ไม่รวมเป็นงบเดียว
- เส้นทางแผน: หน่วยงาน → หัวหน้าแผนก → ฝ่ายแผนฯ → CFO → ผู้อำนวยการ → สสจ.อุดรธานีและรอผล → พัสดุ
- หน่วยงานส่งได้หลายคำขอ ฉบับละหนึ่งรายการ ขอนอกแผนต้องเสนอเพิ่มแผนก่อน หัวหน้าฝ่ายแผนอนุมัติเปิดรอบเพิ่ม และต้องแนบเล่ม PDF ตามขั้นตอน
- ผูกพันเมื่อสัญญา แยกจากจ่ายจริง คำขอเบิกถูกส่งคืนไม่ย้อนเปิดสัญญาเดิม
- เลขครุภัณฑ์เดิม 4 หลักเก็บเดิม เลขใหม่ 5 หลัก ลำดับต่อเนื่องตามคู่รหัสข้ามปี ส่วน /YY เป็นปีได้มา ไม่แก้เลขเก่าเมื่อปีเปลี่ยน
- ออกเลขหลังตรวจรับผ่านเฉพาะเครื่อง ไม่ต้องรอจ่ายเงิน คู่รหัสใหม่ยังต้องทวนสอบ/กำหนดอำนาจก่อนเปิดใช้
- Excel/CSV เป็นช่องทางนำเข้าทะเบียนเดิม ไม่ใช่ทางลัดออกเลขใหม่แทนตรวจรับ
- มีตารางอ้างอิงอายุใช้งานและอัตราค่าเสื่อม สป.สธ. แต่ยังไม่ลงค่าเสื่อมจริง
- คงต้นฉบับหมึกและเชื่อมสำเนา PDF ไม่อ้างว่าการติ๊กตรวจเอกสารเป็นลายเซ็นจริง
- HOSxP ต้องเชื่อมแบบอ่านอย่างเดียวเมื่อได้รับอนุญาต ระบบจริงยังไม่เชื่อม HOSxP, Provider ID, e-GP, ธนาคาร หรือ New GFMIS Thai
- Log อยู่ใต้ตั้งค่าระบบ รายละเอียดแสดง popup ยังเป็น Log ภายในเบราว์เซอร์ ไม่ใช่หลักฐานส่วนกลางที่ผู้ดูแลเครื่องแก้ไม่ได้
- เก็บข้อมูลทดลองใน IndexedDB มีกลไกกันเขียนทับจากแท็บและหน้าจอเก่า ไม่ใช่ฐานข้อมูลกลางหลายผู้ใช้

## 8. รายงานที่ควรพัฒนาต่อ

ระบบรุ่นนี้สร้างสรุปผู้บริหาร 5 ฝ่ายและงานติดขัดจากข้อมูลที่มีได้ ยังไม่แทนรายงานราชการเฉพาะแบบ ไม่สร้างงบการเงิน เงินสดรับรอง ค่าเสื่อมจริง คะแนนยุทธศาสตร์ ประสิทธิภาพซ่อม รายงานตรวจประจำปีครบชุด หรือกำหนดอายุความเอง

ก่อนใช้งานจริงต้องรับรองแหล่งข้อมูล ผังบัญชี นโยบายค่าเสื่อม คำสั่งมอบอำนาจ แบบรายงาน นิยามกำหนดเวลา การเก็บเอกสาร สิทธิ์เข้าถึง PDPA และการเชื่อมระบบกลาง
