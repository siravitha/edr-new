# งานฝ่ายแผนงานและยุทธศาสตร์ — ต้นแบบ

## ขอบเขตที่ผู้ใช้อนุมัติ

- 7 เมนูย่อย: ภาพรวม, คำขอ, จัดทำแผน, เสนออนุมัติ, ปรับแผน, ส่งพัสดุ, ติดตามผล
- ฝ่ายแผนเปิดรอบ กำหนดปี แหล่งเงิน ช่วงเวลา และหน่วยงาน แต่ละหน่วยงานส่งหลายฉบับ ฉบับละรายการ
- คำขอผ่านหัวหน้าหน่วยงานก่อนรวบรวมแผน แผนผ่าน CFO → ผู้อำนวยการ → ส่ง สสจ.อุดรธานี → รอผลอนุมัติ → ส่งพัสดุ
- ทุกรอบมีแหล่งเงินเดียว ไม่รวมเงินงบประมาณ เงินบำรุง และเงินบริจาคในแผนเดียว
- ผู้พิจารณาแก้จำนวน รายละเอียด และวงเงินได้ โดยบันทึกเหตุผล เก็บข้อมูลเสนอครั้งแรกและข้อมูลก่อน/หลัง
- การแก้รายการโดยผู้อำนวยการส่งกลับ CFO เพื่อพิจารณาฉบับใหม่ ป้องกันผล CFO เดิมถูกนำไปใช้กับยอดใหม่
- หลังปิดรอบ เจ้าหน้าที่ขอเปิดเพิ่มเติมได้ แต่หัวหน้าฝ่ายแผนเท่านั้นอนุมัติได้ มีวันเริ่ม/สิ้นสุดและเหตุผล
- รายการนอกแผน/เร่งด่วนต้องเสนอเพิ่มแผน ไม่ข้ามขั้นอนุมัติ สามารถสร้างคำขอเพิ่มในรอบที่เปิดรับ
- เช่าหลายปีแยกแผนจ่ายปีงบประมาณ ตรวจยอดเป็นสตางค์ให้เท่ามูลค่ารวม
- แบบพิมพ์ใหม่รองรับข้อมูลและตราโรงพยาบาล เลขคำขอ/แผน ฉบับ และช่องลงนามหมึก

## วิธีทดลอง

1. เมนูฝ่ายแผนฯ → คำขอความต้องการ ใช้หน้าที่เจ้าหน้าที่ฝ่ายแผน สร้างรอบแล้วเปิดรับ
2. เปลี่ยนหน้าที่จำลองเป็นผู้ขอและเลือกหน่วยงาน เพิ่มคำขอ บันทึกร่าง แล้วเปิดคำขอส่งหัวหน้า
3. เปลี่ยนเป็นหัวหน้าแผนกของหน่วยงานนั้น เปิดคำขอ เห็นชอบ หรือแก้รายการ/วงเงินพร้อมเหตุผล
4. เปลี่ยนเป็นฝ่ายแผน ไปจัดทำแผนประจำปี เลือกรอบและคำขอที่ผ่านหัวหน้า สร้างร่างแผน
5. หน้าเสนออนุมัติ เปิดแผนแล้วเสนอ CFO ใช้หน้าที่ CFO บันทึกมติ จากนั้นผู้อำนวยการบันทึกหลักฐานอนุมัติ
6. ฝ่ายแผนบันทึกเลขหนังสือนำส่งและวันที่ เลือกหน้าที่บันทึกผล สสจ. เพื่อบันทึกหนังสือตอบกลับ ผล และหลักฐาน
7. ฝ่ายแผนส่งแผนที่อนุมัติแล้วให้ฝ่ายพัสดุ ดูรายการได้ที่พื้นที่การทำงาน → ฝ่ายพัสดุกลาง ไม่สร้าง PR/PO อัตโนมัติ

## ข้อจำกัดที่ต้องแสดงอย่างชัดเจน

ข้อมูลอยู่ IndexedDB ของเบราว์เซอร์ ใช้ Web Lock และ revision ป้องกันเขียนทับในต้นแบบ ไม่ใช่ระบบหลายผู้ใช้จริง หน้าที่และหน่วยงานเลือกเพื่อทดลองเท่านั้น ไม่มีการยืนยันสิทธิ์จาก Provider ID และไม่มีการอนุมัติราชการจริง

ประวัติเป็นรายการเพิ่มต่อท้ายในข้อมูลต้นแบบที่แก้ไขได้จากเครื่อง ไม่ใช่ audit log ที่ป้องกันผู้ดูแลแก้ไข ระบบจริงต้องใช้ฐานข้อมูลฝั่งเซิร์ฟเวอร์ ธุรกรรม เลขลำดับเฉพาะโรงพยาบาล ตรวจอำนาจจากคำสั่งแต่งตั้ง และที่เก็บหลักฐานที่มีการควบคุมสิทธิ์

เอกสารประกอบของคำขอเก็บคำอธิบาย/เลขอ้างอิง ส่วนแผนต้องแนบเล่ม PDF ในหน้าจัดสรรและเสนออนุมัติงบประมาณ การพิมพ์ไม่ได้ยืนยันความถูกต้องของลายเซ็น ไม่มีการส่งหนังสือจริงหรือเชื่อม สสจ., HOSxP, e-GP หรือระบบการเงิน

ขณะออฟไลน์อนุญาตเฉพาะบันทึกร่างรอบและร่างคำขอในเครื่อง การส่งและอนุมัติถูกระงับ ไม่ได้เปิดนโยบาย offline sync จริงที่ยังไม่กำหนด

วงเงินแผนเป็นวงเงินเสนอ/อนุมัติ ไม่ใช่เงินผูกพันหรือยอดจ่ายจริง ไม่มีการหักงบหรือสร้างรายการบัญชี การปรับแผนที่อนุมัติแล้วใช้คำขอเพิ่มและกระบวนการแผนใหม่ ไม่แก้ฉบับอนุมัติทับ ระบบเชื่อมโยงลดวงเงินแผนเดิมที่มีสัญญาอยู่ยังไม่เปิดใช้งาน

## การตรวจสอบ

ทดสอบกติกาใน tests/planning.test.mjs ครอบคลุมการส่งหลายฉบับ ขอบเขตหน่วยงาน การเปิดเพิ่มเติม การคงต้นฉบับ การแยกแหล่งเงิน แผนเช่า ลำดับอนุมัติ การส่งกลับ ฉบับใหม่ และการห้ามส่งพัสดุก่อนผล สสจ.

ตรวจผ่านหน้าจอ 1 พฤศจิกายน 2569: สร้าง RND-0001 → REQ-0001 → หัวหน้าเห็นชอบ → PLN-0001 → CFO แก้ยอด 50,000 เป็น 45,000 สร้างฉบับ 2 → ผู้อำนวยการ → หนังสือนำส่ง → ผล สสจ. → ส่งฝ่ายพัสดุ ตรวจพบแผนในกล่องรับและข้อมูลคงอยู่หลังโหลดหน้าใหม่ ข้อมูลทดสอบอยู่เฉพาะ localhost ไม่ถูกรวมในชุดเผยแพร่

## เล่มเอกสาร PDF (เพิ่มตามคำขอ)

ฝ่ายแผนฯ ต้องแนบ PDF รวมเล่มก่อนเสนอ CFO และบันทึกนำส่ง สสจ.อุดรธานี รวมถึงก่อนบันทึกผล CFO/ผู้อำนวยการ จำกัด 10 MB ตรวจนามสกุล MIME ส่วนหัวและส่วนท้ายเบื้องต้น พร้อม SHA-256 ผู้แนบยืนยันว่าเอกสารตรงกับรายการและวงเงิน ระบบตรวจไม่ได้ว่าเนื้อหาหรือลายเซ็นในไฟล์ถูกต้อง

เก็บ Blob แยกใน IndexedDB รุ่น 2 บันทึกไฟล์และข้อมูลแผนในธุรกรรมเดียว ใช้ add ป้องกันเขียนทับไฟล์เดิม เก็บชื่อ ขนาด hash ผู้แนบ วันเวลา และฉบับในประวัติ การแก้รายการโดยผู้พิจารณาหรือส่งแผนกลับทำให้เล่มเดิมใช้ต่อไม่ได้ ต้องแนบเล่มตรงฉบับใหม่ ไฟล์เก่าดาวน์โหลดได้จากประวัติ หลังนำส่ง สสจ.แล้วเปลี่ยนไฟล์ไม่ได้

ข้อมูลเก็บเฉพาะเบราว์เซอร์ ไม่ใช่ระบบคลังเอกสารส่วนกลางและไม่ส่งหนังสือถึง สสจ.จริง การล้างข้อมูลเว็บทำให้ไฟล์หาย ควรเก็บต้นฉบับภายนอก ระบบใช้งานจริงยังต้องมีสิทธิ์ฝั่งเซิร์ฟเวอร์ ที่เก็บไฟล์พร้อมสำรองข้อมูล การสแกนมัลแวร์ การตรวจ PDF ที่ครบถ้วน และกติกาอายุเก็บเอกสาร ไม่ถือว่าการตรวจส่วนหัวเป็นการรับรองความปลอดภัย
