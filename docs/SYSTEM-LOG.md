# Log system

เมนูตั้งค่าระบบ → Log system รวมประวัติเดิมและประวัติของทุกกระบวนการที่ต้นแบบเปิดให้ทำรายการจริง ไม่ได้หมายความว่าทั้ง 15 ขั้นตอนมีระบบอนุมัติจริงครบแล้ว หน้าวงจร 15 ขั้นตอนที่เป็นแค็ตตาล็อกบันทึกเป็นการเข้าดูขั้นตอน แยกจากการเปลี่ยนสถานะธุรกิจ

## การบันทึก

- เพิ่ม แก้ไข ระงับ ยกเลิกข้อมูลผู้ใช้ รหัสเอกสาร แผนก ผู้ค้า และข้อมูลโรงพยาบาล
- เปิด/ปิดรอบ ขอและอนุมัติเปิดเพิ่มเติม คำขอ การพิจารณา ปรับวงเงิน รวบรวมแผน CFO ผู้อำนวยการ หนังสือ สสจ. และส่งพัสดุ
- แนบ/เปลี่ยน PDF เก็บชื่อ ขนาด แฮช ฉบับ และข้อมูลเปลี่ยนแปลง ไม่เก็บ Blob ลงใน Log
- สแกน เปลี่ยนสถานะทรัพย์สิน เก็บคิวออฟไลน์ ผลซิงก์ ข้อขัดแย้ง และนำเข้า CSV
- คำขอเบิกจ่าย ส่งคืน เสนอใหม่ อนุมัติจำลอง และการทดลองผูกพัน/จ่ายเงินในหน้าวงจร
- ผลปฏิเสธจากกติกาและการตรวจข้อมูล การขอพิมพ์ ดาวน์โหลด ส่งออก เข้าดูรายละเอียด เปลี่ยนบทบาทจำลอง และเปิดแอป
- รีเซ็ตข้อมูลทดลองเป็นเหตุการณ์แยก ประวัติ Log ไม่ถูกลบพร้อมชุดข้อมูลธุรกิจ

การกรอกตัวอักษร ตัวกรอง และร่างที่ยังไม่กดบันทึกไม่ใช่รายการธุรกิจที่สำเร็จ ไม่มีการบันทึกทุกคีย์เพื่อหลีกเลี่ยงข้อมูลส่วนบุคคลที่ไม่จำเป็น การขอพิมพ์บันทึกว่า PRINT_REQUESTED ไม่กล่าวอ้างว่าพิมพ์กระดาษสำเร็จ

## ความครบถ้วนและการจัดเก็บ

IndexedDB รุ่น 3 เพิ่ม systemLogs (ลำดับเพิ่มอัตโนมัติ) และ systemLogMeta (นำเข้าประวัติเดิมครั้งเดียว) การเปลี่ยนข้อมูลธุรกิจ ไฟล์ PDF และ Log สำเร็จหรือยกเลิกพร้อมกันในธุรกรรมเดียว ไม่มีการตัดทิ้ง Log อัตโนมัติ ไม่มีคำสั่งแก้ไข/ลบ Log ในแอป ประวัติเดิมที่ไม่มีเวลาเหตุการณ์แสดงว่าไม่ทราบ แยกเวลาเข้าคลังออกจากเวลาเหตุการณ์จริง

เก็บ eventId, ลำดับ, เวลา, ผู้ทำรายการ/หน้าที่/หน่วยงานจำลอง, sessionId, deviceId, หน้าจอ, หมวดงาน, การกระทำ, รายการอ้างอิง, ผล, เหตุผล และข้อมูลก่อน/หลัง ปกปิด token รหัสผ่าน ข้อมูลติดต่อ เลขทะเบียนส่วนบุคคล และเนื้อหาไฟล์ ไม่สร้าง IP หรือ Provider ID ขึ้นเองเพราะต้นแบบไม่มีการยืนยันข้อมูลดังกล่าว

Log อาจมีทั้งเหตุการณ์จากกติกาเดิมและเหตุการณ์เปลี่ยนข้อมูลรายรายการ จึงอาจเห็นหลายเหตุการณ์ในธุรกรรมเดียว ตั้งใจให้ตรวจได้ทั้งขั้นตอนและผลข้อมูล ไม่ถือเป็นการนับจำนวนธุรกรรมทางบัญชี

## สิทธิ์และหน้าจอ

แสดงแก่หน้าที่จำลองผู้ดูแลระบบและผู้ตรวจสอบ ค้นหา กรองหมวด ผล ช่วงวัน แบ่งหน้า 50 เหตุการณ์ ดูก่อน/หลัง และส่งออก CSV ได้ การอ่านรายละเอียดและส่งออกก็มี Log ไม่มีสิทธิ์แก้ไขหรือลบผ่านหน้าจอ

## ข้อจำกัดก่อนใช้งานจริง

เป็นคลังในเบราว์เซอร์เท่านั้น ไม่รองรับการรับรองการตรวจสอบภาครัฐอย่างสมบูรณ์ ผู้ควบคุมเบราว์เซอร์แก้หรือล้างข้อมูลได้ หน้าที่จำลองไม่ใช่การตรวจสิทธิ์ฝั่งเซิร์ฟเวอร์ ระบบจริงต้องมี append-only storage ฝั่งเซิร์ฟเวอร์ ตัวตนและสิทธิ์จากระบบที่เชื่อถือได้ เวลาเซิร์ฟเวอร์ ธุรกรรม/outbox การป้องกันแก้ย้อนหลัง การติดตามเมื่อ Log ขัดข้อง และนโยบายเก็บรักษาที่โรงพยาบาลอนุมัติ โดยไม่เปิดให้อนุมัติธุรกิจสำเร็จเมื่อเก็บ Log ไม่ได้
